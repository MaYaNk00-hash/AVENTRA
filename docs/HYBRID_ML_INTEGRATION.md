Current UI: provider-independent Operations Console plus optional Gemini assistance. All 110 backend tests now pass; prior failure counts below are historical. See PROTOTYPE_OPERATIONS.md.

AVENTRA now combines Gemini tool selection with read-only inference from all
eight existing artifacts in `ml/models/*/artifacts/`. No model, training data,
or trained artifact is retrained, overwritten, or replaced by this integration.

Open **ML intelligence** in the main workspace. The eight cards report actual
artifact deserialization/estimator status, version, implementation, and SHA-256.
Selecting a card fills a clearly labeled synthetic input example. Edit the input
and request, then choose **Run Gemini + local inference**. Gemini receives the
request and the available model/input field names, not the structured input
values. The backend validates its selection, runs the corresponding artifact,
saves the exact inputs and outputs, and appends a model/version/hash audit entry.
Missing or corrupt artifacts fail explicitly without baseline training or a
fabricated prediction. Local intent classification also precedes ordinary
Gemini workflow requests; it never grants permissions. Entity matching in the
connected-data flow uses the same verified read-only adapter.

| Artifact | Active adapter behavior |
| --- | --- |
| Entity resolution | Existing LightGBM feature preprocessing and pair scores |
| Semantic schema mapper | Saved TF-IDF and Logistic Regression field classification |
| Intent parser | Saved TF-IDF and Logistic Regression classes and probabilities, plus separate deterministic injection-pattern checks |
| Workflow planner | Saved template lookup and DAG validation; no learned estimator, probability, or automatic execution |
| Invoice reconciliation | Saved Decision Tree inference on its six trained comparison features |
| Adaptation recommender | Saved Decision Tree breaking-change inference on similarity and type-shift features |
| Document intelligence | Existing deterministic invoice parsing plus actual Ridge artifact scoring of extracted numeric features |
| Anomaly detection | Saved Isolation Forest prediction, score_samples, and decision_function; no fraud probability |

The invoice adapter expects `po_total`, `inv_total`, `price_variance`,
`qty_variance`, `tax_diff`, and `has_exceptions`. These are the artifact's training
features, not a complete proof of three-way reconciliation. Its labels were
generated by training rules; a classifier result never authorizes a payment.
The adaptation adapter expects `semantic_similarity` (0..1) and
`has_type_shift` (0 or 1). The document regressor score is not calibrated
correctness probability. The adapters deliberately avoid the fixed confidence
constants and fallback predictions in some older wrappers.

Artifact provenance is reported conservatively. Several training scripts create
synthetic scenarios; adapter inventory does not treat registry/configuration
metric constants as measured held-out evaluation results. Evaluation metrics
remain unavailable until an actual evaluation report is verified. These smoke
checks prove loading, integration, and execution, not accuracy on every input.

Authenticated endpoints:

- `GET /api/runtime/intelligence/models`: actual artifact inventory.
- `POST /api/runtime/runs`: pass `source_ids: []`, `planner: "gemini"`, a `goal`,
  and the original structured object in `analysis` for independent ML analysis.
- `GET /api/runtime/runs/{id}`: persisted inputs, outputs, Gemini selection,
  artifact versions/hashes, local inference duration, and execution trace.

Analysis uses no connected source services and executes no enterprise writes.
Ordinary CRM/ERP data workflows still require their configured services, including
the local sandbox on port 8100 when that connection is selected. Real writes
retain existing role checks, proposal review, conditional execution, and
verification. Template nodes are proposals only; this integration does not run
their payment, merge, or migration actions.
